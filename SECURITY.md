# Безопасность / Security

FlitCMS — лёгкая CMS без внешних зависимостей. Часть защиты лежит на самой CMS, часть — на том, кто её разворачивает.
Ниже то, что нужно сделать **до выхода сайта в интернет**.

## 1. Закройте служебные папки веб-сервером (обязательно)

В корне сайта лежат файлы, которые не должны отдаваться браузеру:

| Папка | Что внутри |
|---|---|
| `data/` | пользователи (`user.json`, хеши паролей) и сообщения |
| `log/` | журнал, в нём бывают пути и email |
| `config/` | настройки, пароль MySQL, языковые файлы |
| `includes/` | код классов |
| `cache/` | скомпилированные шаблоны |
| `templates/` | исходники шаблонов |

Открытыми должны остаться только `index.php`, `ajax.php` и `assets/`.

**nginx** (в `server { ... }`, выше блока `location ~ \.php$`):

```nginx
location ~ ^/(data|log|config|includes|cache|templates)/ { deny all; return 404; }
location ~ \.(py|log|json|md|psd)$ { deny all; return 404; }
location ~ /\. { deny all; }
```

**Apache** (в виртуальном хосте):

```apache
<LocationMatch "^/(data|log|config|includes|cache|templates)/">
    Require all denied
</LocationMatch>
<FilesMatch "\.(py|log|json|md|psd)$">
    Require all denied
</FilesMatch>
```

Если доступа к настройкам хоста нет, положите в каждую из этих папок файл `.htaccess` с одной строкой `Require all denied`.

Проверьте результат: `https://ваш-сайт/data/user.json` и `https://ваш-сайт/config/config.inc.php` должны отдавать 403 или 404.

Лучший вариант — вынести `data/`, `log/` и `config/` **за пределы** папки сайта и поправить пути в `config.inc.php`.

## 2. HTTPS

Включите HTTPS (например, Let's Encrypt). Кука сессии помечается `Secure` автоматически, когда сайт открыт по HTTPS, и всегда `HttpOnly` и `SameSite=Lax`.

## 3. Администратор и регистрация

- Действия админки в `ajax.php` (пользователи, настройки, логи, кэш, переводы) разрешены только роли `admin`. Без входа доступны только `login`, `register_user`, `sendMessage` и `get_valid_languages`.
- Публичная регистрация (`register_user`) всегда создаёт роль `user`; роль `admin` может назначить только вошедший администратор. Первого администратора создают через `create-admin.php`.
- **`create-admin.php` работает без входа в систему. Удалите его сразу после первой настройки** (иначе любой посетитель сможет создать себе администратора). Для nginx/без `.htaccess` можно дополнительно ограничить доступ к нему по IP.
- `stats.php` отдаёт данные только администратору.
- Последнего администратора нельзя удалить или понизить из админки.
- Создайте администратора сразу после установки и используйте длинный уникальный пароль.

## 4. Файлы и права

- Пользователь веб-сервера должен иметь право записи только в `data/`, `log/`, `cache/`, `config/lang/` и `config/config.inc.php` (последний нужен разделу «Настройки»). Остальной код лучше сделать доступным только для чтения.
- Не храните резервные копии (`*.zip`, `*.bak`, `*.psd`) и служебные скрипты (`ftpp_send_*.py`, `new_ver_*.py`) в папке сайта.
- В `config.inc.php` смените пароль MySQL и адрес администратора, если они остались от примера.

## 5. PHP

В `php.ini` для боевого сайта:

```ini
display_errors = Off
expose_php = Off
session.use_strict_mode = 1
```

## 6. Обновления и резервные копии

Следите за релизами в репозитории и делайте регулярную копию `data/` и `config/`.

## 7. Нашли уязвимость?

Напишите владельцу репозитория приватно (Security → Report a vulnerability на GitHub) и не публикуйте детали, пока ошибка не исправлена.
